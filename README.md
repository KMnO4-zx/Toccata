# Toccata

一个 macOS 本地任务与键盘活跃工作台。想到的事情先放进收集箱，回顾时一起整理期间完成和当前未完成的任务；键盘活动在工作台里显示为时间线。

名字取自「触键曲」（toccata，词根 toccare = 触碰）。

当前版本：**v0.0.8**，用于正式开源前的开发与体验；正式开源首版计划使用 **v0.1.0**。安装包适用于 Apple Silicon Mac，macOS 13 或更新版本。

## 版本与更新

主界面左侧栏底部提供“关于 Toccata”入口，右侧显示当前版本，点击即可查看版本信息与检查更新。也可以从 macOS 顶部应用菜单、状态栏图标的右键菜单或设置页底部进入。关于窗口显示版本并支持复制版本信息，方便反馈问题；同时提供可点击的 GitHub 仓库入口。构建号仅保留在打包元数据中，不在关于页或复制内容中展示。

“检查更新”由用户手动触发，读取本仓库公开的 [GitHub Releases](https://github.com/KMnO4-zx/Toccata/releases) 最新正式版本，按主版本、次版本、修订版本的数字比较，不推荐降级，也不推荐草稿或预发布版本。发现新版后可打开对应发布页面，查看更新说明并自行下载、安装；应用不会自动下载安装。

版本查询使用 GitHub 的 [Latest Release API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

检查时只向 GitHub 请求版本信息，不上传任务或键盘记录，也不使用 GitHub 登录凭据。仓库仍为私有、尚无正式发布、网络失败或请求受限时会显示具体提示，不能检查时不会显示“已是最新版”。仓库公开并发布正式版本后，无需重新配置应用即可检查。

## 任务怎么用

- **想到就记**：在任务列表或菜单栏快速添加任务。新任务默认没有计划日期，也不会自动成为“今天必须完成”的任务；创建时间单独记录，计划日期可按需要设置。
- **按任务视图查看**：工作台侧栏统一进入“任务”，默认显示本周，可在页面内切换“本周 / 最近 7 天”。最近 7 天按创建时间筛选，本周汇集本周创建、之前遗留未完成和本周完成的任务；两个范围都保留符合条件的已完成任务。“收集箱”仍是独立入口，保留全部顶层任务。菜单栏继续使用“收集箱 / 最近 7 天 / 本周任务”三个范围，默认显示本周任务。
- **按主任务整理子任务**：任务、收集箱和任务日历中的子任务缩进排列在对应主任务下方，可逐组收起。默认“仅标题”，切换“标题与描述”可预览主任务及子任务各自的描述，显示方式会在页面之间同步保存。日期筛选仍按各任务的实际日期；仅为说明归属而补充的父任务不产生额外日期记录。
- **菜单栏直接编辑**：点击状态栏图标打开 312 × 554 pt 的紧凑任务列表，每项标题单行显示，不常驻显示创建时间副行，创建时间仍完整记录并用于视图筛选。子任务缩进显示在父任务下方，可折叠展开，已完成任务也保留层级。点击任务会在列表左侧打开独立的 400 × 300 pt 小浮窗，首次出现时轻快浮现，可编辑标题、Markdown 描述、计划日期及子任务，通过旗标设置优先级；原列表保持原有宽度并持续可见。选中任务后，按 Tab 定位到描述；选中顶层任务时，按 Enter 定位到添加子任务，子任务没有继续新增下级的入口；描述中的 Enter 仍然换行。右键或“更多操作”可删除任务，删除前会确认并说明子任务联动。
- **菜单栏快捷导航**：底部提供任务、日历、工作台三个图标。日历在面板内展开月历，可翻月、回到今天并查看或编辑当天任务；窗口图标直接打开工作台。点击状态栏只展开任务浮窗，工作台在后台时保持原来的窗口顺序；明确打开工作台才将其带到前台。右键状态栏图标可设置外观、登录时启动、查看快捷键或退出应用。
- **切换外观**：在主界面侧栏底部、应用设置或状态栏图标的右键菜单中选择“月之亮面”（浅色）、“月之暗面”（深色）或“跟随系统”。侧栏会显示当前选择；默认跟随系统，选择会自动保存，工作台、任务浮窗和 Markdown 编辑区同步切换。
- **用 Markdown 写详情**：每个任务可用 Markdown 整理背景、链接、列表和代码，在同一个可编辑区域中直接显示和修改排版，无需切换预览。详情统一保存为 Markdown 原文，子任务也有独立详情，但不能继续创建下级任务。历史过程数据继续保留在原有数据库表中，不再提供独立的过程记录入口。
- **保留完成记录**：菜单栏的完成状态显示为圆内对号，完成保存成功后响起一声清亮的“叮”，尾音自然消散，快速连续完成时不会叠加声音，恢复待办不播放。完成任务后仍可在收集箱的“已完成”区域查看、展开详情或恢复为待办。
- **在任务月历里查看**：可按创建、计划、完成或全部事件查看任务，选择日期后可查看、编辑当天任务。同一任务在一天内只列一次；没有计划日期的任务另列。常规新增仍不设置计划日期，只有明确选择按所选日期新建才会安排到当天。
- **为任务安排日期**：主界面和菜单栏的任务详情使用同一款日历浮窗，支持选择未来日期，以及今日、明日、下周一快捷选择。点击“确定”保存，取消保留原日期，也可以清除已有日期。
- **一起回顾完成与待办**：“任务回顾”默认显示本周，可切换最近 7 天或自定义时段。在浮动日历中依次选择开始、结束日期并应用，即可查看该范围；选择同一天可回顾单日，取消不会改变当前范围。分组展示所选期间完成的任务与当前全部未完成任务，包含子任务和之前遗留的待办。已完成部分依据实际 `completedAt` 筛选，创建日期和计划日期不影响归档；未完成部分不受创建日期限制。
- **准备周报素材**：可搜索任务名称与详情，并复制当前回顾为周报素材，包含完成与未完成分组、各组数量、任务详情和子任务的父级路径。自动按模板生成周报尚未实现。

回顾列表按主任务归组，已完成子任务仍嵌套在所属主任务下面；顶部摘要按实际任务数统计，列表分组按主任务组数显示。任务列表和菜单栏的子任务展开、收起使用轻微的位移与淡入淡出，箭头同步旋转，并遵循系统的减少动态效果设置。

子任务右侧提供三条横线的拖拽手柄，按住手柄后，整行会随鼠标上下移动，松手后保存排序；拖到另一子任务的上半行或下半行可插入其前后，插入位置会显示细线。移动仅限同一主任务、同一完成状态内；未完成始终在上，已完成始终在下。顺序保存到本机任务库，在工作台、状态栏、日历、回顾和详情中同步；菜单栏顶部的排序只调整主任务。筛选隐藏的子任务仍保留原有相对顺序，拖出有效区域或按 Esc 取消时，行会回到原位且不改变顺序。

日期范围按本机时区计算：“本周”从周一零点到当前时刻；“最近 7 天”从六天前零点到当前时刻，覆盖含今天的七个自然日。自定义时段包含首尾两个日期的完整自然日，当前日期只统计到当前时刻。任务页面也会列出符合条件的子任务，较早创建的父任务不会遮住新进展。“任务回顾”的时间范围用于筛选已完成事项，当前尚未完成的事项会一并保留，方便整理后续安排；复制回顾使用相同日期范围和搜索条件。

完成父任务会同时完成尚未完成的子任务，保留已完成子任务的原完成时间。恢复一个任务会同时恢复其已完成的祖先，保留其他已完成子任务；给已完成父任务新增子任务也会恢复父任务。删除父任务会一并删除其子任务。

## 键盘活跃怎么计算

“键盘活跃”依次显示活动概览、逐键热度和活跃时间线。概览与键盘热力图统一支持今日、昨日、最近 7 天、本周和自定义时段；自定义时段的起止日期相同即查看单日。热力图上方显示所选时段次数最多的五个按键及各自次数，随范围一起更新；有记录的按键不足五个时只显示实际项。悬停按键可查看所选范围内的次数，Fn 键显示对应的累计按住时长。时间线默认跟随上方范围，也能单独查看今日、昨日或日历中选择的指定日；每格代表 15 分钟，悬停可查看具体时段、活跃时长、Fn 按住时长和按键次数。

时间范围右侧的“分享”会打开图片预览，包含所选时段的三项统计、键盘热力图、常用前五键、逐日活跃时间线，以及按活跃时长排序的前六个应用（图标、时长、按键次数）。图片采用适合手机查看的紧凑纵向排版，突出统计数字和应用信息，底部附有 GitHub 仓库地址。分享统一采用顶部范围，不受时间线或应用页的独立筛选影响。各区块从同一份已保存记录生成，预览期间固定内容；刚输入且尚未落盘的活动在保存后重新打开预览即可纳入。可复制 PNG 图片到剪贴板，或通过保存对话框选择目录，默认下载目录。图片在本机生成，不上传活动数据。

时长不足 600 秒时以秒显示，保留至多一位小数；从 600 秒起显示为“10分36秒”，满一小时显示为“1小时36分12秒”。活动概览、悬浮提示和应用使用时长采用同一格式。

“应用与趋势”上方展示最近 26 周的活跃日历，下方是紧凑的应用活跃度列表。活跃日历可折叠，颜色越深表示当天按键次数越多；悬停可查看日期和按键次数，不足 1,000 次显示原数字，从 1,000 次起以 K 显示，最多两位小数（例如 `1.05K`、`10.33K`）。应用列表显示本机应用图标、名称、估算使用时间和按键次数，可切换今日、昨日、近 7 日、近 30 日，或通过日历选择指定日。键盘与应用统计在切换日期范围时采用轻微过渡动画，并尊重系统的减少动态效果设置。

活跃时长采用**短窗口合并**，默认窗口为 **5 秒**：

- 每次有效按下覆盖从按下时刻开始的后续 5 秒；松开按键不会再增加一个窗口。长按产生的重复输入事件会过滤。
- 把所有窗口与实际按住按键的区间合并，重叠部分只算一次；没有被覆盖的停顿不计入。
- 统计最多计算到当前时刻，并按所选日期边界裁剪；跨午夜的活动分配到对应日期和 15 分钟时间格。
- Fn 累计按住时长单独按实际按住区间合并，不添加 5 秒窗口。

例如，在相关活动及窗口结束后查看时：

| 输入情况 | 计入的活跃时长 |
|---|---|
| 第 0 秒和第 3 秒各短按一次 | 两个窗口覆盖第 0～8 秒，共 8 秒 |
| 第 0 秒和第 40 秒各短按一次 | 两段独立的 5 秒窗口，共 10 秒，中间停顿不计入 |
| 从第 0 秒到第 20 秒持续输入，按下间隔不超过 5 秒 | 连续覆盖到第 25 秒，共 25 秒 |
| 只按住一个键 12 秒后松开 | 实际按住区间覆盖原窗口，共 12 秒 |

键盘概览、时间线与应用活跃度使用同一窗口规则。键盘页结合已落盘事件和实时事件重建，当前连接中观察到的长按可持续增长；断线后遗留的孤立按下事件不会无限累加。应用列表按事件记录的应用归属分别合并已落盘区间，尚未松开的长按在配对落盘后补全；不同应用的窗口可能重叠，列表时长不宜直接相加作为全局时长。

已有原始事件会按新规则重新计算，历史活跃时长可能缩短；按键次数与历史记录保留。

这些数字是**根据键盘活动估算的电脑使用时间**。阅读、看视频、仅使用鼠标时可能没有记录。**Fn 累计按住时间用于估算语音输出时间**，也可能包含 Fn 快捷键操作；Toccata 不检测麦克风录音。

键盘采集由 Rust 后台服务运行，记录键码、时间、按住时长和前台应用归属。标准 App 已内嵌该服务，并会在现有 socket 不可连接时自动启动；已有可用服务会直接复用。任务功能可独立使用，后台服务未连接时仍能添加、编辑和完成任务。

## 构建与运行

需要 macOS 13 或更新版本、Rust 工具链和支持 Swift 5.9 的 Xcode Command Line Tools。

项目 Logo 使用侧栏同款蓝色叠层标志。运行 `swift scripts/generate-branding.swift` 可重新生成 `shared/branding/` 下的 PNG 和打包用的 `AppIcon.icns`。

```bash
# 在项目根目录：构建工作台及内嵌采集服务，产物为 dist/Toccata.app
./scripts/build-app.sh
open dist/Toccata.app

# 开发时也可单独构建并启动键盘采集服务
cargo build --release --locked
./target/release/toccata-core
```

打包默认使用 ad-hoc 签名，不需要钥匙串中的签名身份。已有签名身份时，可通过 `TOCCATA_SIGN_IDENTITY` 显式指定；使用受钥匙串保护的身份可能需要额外的授权。更换代码签名身份后，macOS 可能要求重新授予输入监控权限。

关闭工作台窗口后，Toccata 会继续在菜单栏运行，键盘采集和任务快捷入口保持可用；可从菜单重新打开工作台。选择“退出 Toccata”会先保存任务修改，再等待 App 自己启动的采集服务保存数据后退出；独立启动的服务仍由其原有启动方式管理。

“登录时启动”默认关闭，可通过设置菜单自行开启或关闭；构建与打包不会修改登录项。登录自动启动时只显示菜单栏图标，不会主动打开工作台或请求输入监控权限；需要时可从菜单打开工作台。如果 macOS 要求允许登录启动，菜单会提供“前往系统设置允许启动”的入口。

首次启动采集服务需要在“系统设置 → 隐私与安全性 → 输入监控”中手动开启 Toccata；部分 macOS 版本不会显示授权弹窗。服务会在等待授权时定期重试。App 会启动内嵌服务，不需要另行手工启动；SwiftPM 开发构建没有内嵌服务，可使用上面的独立运行方式。

妙控键盘的 F1–F12（包括亮度、媒体等顶部功能）、Caps Lock 和 Lock 额外通过原始 HID 按键事件采集，并与普通键盘监听去重。Caps Lock 按实际点击计数，开启和关闭都计入；Lock 仅记录一次点击，不把锁屏时间计为长按。此监听随采集服务退出而关闭，复用输入监控授权，不独占设备或修改键位。旧版漏记的事件无法补回，历史数据保持原样。

### 生成与安装 DMG

```bash
# 先构建 App，再生成压缩只读磁盘映像
./scripts/package-dmg.sh

# 已构建 dist/Toccata.app 时，直接验证并打包
./scripts/package-dmg.sh --skip-build
```

产物为 `dist/Toccata-<version>-<arch>.dmg`，版本取自 App 的 `CFBundleShortVersionString`，架构根据工作台与内嵌服务的实际二进制判定（`arm64`、`x86_64` 或 `universal`）。脚本会检查两者的签名和架构一致性，使用 `hdiutil` 生成 UDZO 格式并验证映像，输出 SHA-256 及同名 `.sha256` 文件；重复运行会在新包验证成功后替换同版本、同架构的旧产物。

应用版本与构建号统一维护在 `shared/app-version.json`，当前为 `0.0.8` / 内部构建号 `13`。资源同步脚本将它复制到 SwiftPM 资源中，App 打包时写入 `Info.plist`，侧栏、关于窗口、设置页和 DMG 文件名均使用该版本。Rust 包版本必须与应用版本一致，否则构建会停止；升级时同时更新 `core/toccata-core/Cargo.toml` 与 `Cargo.lock`。构建号独立递增，不参与公开版本更新比较。

DMG 包含 `Toccata.app`、指向“应用程序”的快捷方式和安装说明。打开 DMG 后，由用户将 App 拖入“应用程序”，推出磁盘映像，再从安装位置启动；建议完成安装后再开启“登录时启动”。打包脚本只生成文件，不会安装、启动 App，也不会更改登录项或系统权限。

默认 ad-hoc 包用于本机开发与验证，脚本没有执行 Apple 公证。`TOCCATA_SIGN_IDENTITY` 仅选择代码签名身份；正式对外分发还需配置 Developer ID 签名与 Hardened Runtime，并完成 Apple 公证和票据装订。生成 DMG 本身不代表已经满足这些分发要求。

### 手动发布到 GitHub Releases

工作流位于 `.github/workflows/release.yml`，**仅支持手动触发**，推送提交或标签不会自动发布。工作流文件合并并推送到默认分支后，在 GitHub 的 **Actions → Release Toccata → Run workflow** 中执行：

1. 选择 `main`，填写与版本文件一致的标签，如 `v0.0.8`；其他分支不会执行发布构建。
2. `mode` 默认是 `draft`：测试、构建并验证 DMG，然后创建带安装包和 SHA-256 文件的 Release 草稿。检查草稿后，由用户在 GitHub 点击发布。
3. 仅在明确准备发布时选择 `publish`：先创建草稿并上传附件，全部成功后发布为正式版本，标记为 Latest。

工作流在 macOS ARM runner 上构建 Apple Silicon 安装包，运行 Rust 测试及不依赖 WebKit 桌面的 Swift 测试，随后验证签名、架构、磁盘映像和 SHA-256。它按触发时的确切提交构建，发布说明来自 `docs/releases/<tag>.md`；构建任务只有读取权限，发布任务单独使用仓库提供的 `GITHUB_TOKEN` 写入 Releases，不需要在应用内嵌任何令牌。

已有同名 Release 或标签时工作流停止，不覆盖现有附件或移动标签。上传失败可能留下草稿，应先在 GitHub 检查，再决定删除草稿重试或手动处理。正常的草稿审核后发布直接在 GitHub 操作，无需以相同标签重跑工作流。安装包仍采用上述 ad-hoc 签名，工作流不包含 Apple 公证。

版本升级时更新版本文件、Rust 版本与锁文件、同步资源、README 当前版本和对应发布说明，再提交审核。本地打包不会创建标签、发布 Release 或修改仓库可见性。

也可直接通过 SwiftPM 构建界面：

```bash
./scripts/sync-assets.sh
cd apps/toccata-studio
swift build -c release
./.build/release/toccata-studio
```

如果需要在未打开 App 时也随登录启动独立服务，可使用 `scripts/com.toccata.core.plist`：先将其中 `ProgramArguments` 改为实际服务可执行文件的绝对路径，再安装并加载：

```bash
mkdir -p "$HOME/Library/LaunchAgents"
cp scripts/com.toccata.core.plist "$HOME/Library/LaunchAgents/"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.toccata.core.plist"
```

标准 App 不需要安装 LaunchAgent；手工服务与 LaunchAgent 仅用于开发或自定义常驻部署。

## 数据与配置

默认全部保存在 `~/Library/Application Support/Toccata/`：

| 文件 | 用途与写入方 |
|---|---|
| `tasks.sqlite` | 任务、子任务、日期、优先级和 Markdown 详情；历史过程表仅为兼容保留，Studio 独立读写 |
| `toccata.db` | 原始键盘事件与历史应用会话；后台服务独占写入，Studio 只读 |
| `toccata.sock` | 后台服务的实时 JSON Lines 订阅接口 |
| `config.json` | 后台服务配置；Studio 跟随其中的数据库、socket 路径及活跃估算参数 |
| `toccata.lock` | 后台服务的单实例锁 |
| `core.log` | 由 App 启动的 helper 的启动、权限与写入错误日志，不记录键名或文本 |

SQLite 使用 WAL 模式。已有 `toccata.db` 和历史记录继续保留；任务存储在单独的 `tasks.sqlite` 中。

`config.json` 所有字段均可省略，默认值如下：

```json
{
  "activity_window_secs": 5,
  "idle_gap_secs": 60,
  "trailing_grace_secs": 5,
  "flush_interval_secs": 2,
  "flush_batch_size": 500,
  "db_path": null,
  "socket_path": null
}
```

`activity_window_secs` 控制 Studio 的短窗口长度，修改后重启 App 生效。`idle_gap_secs` 与 `trailing_grace_secs` 仅用于后台兼容保留的 `app_sessions` 会话记录；当前键盘活跃与应用活跃度从原始事件计算，不再依赖该表或这两个旧参数。

后台服务每 2 秒按固定周期批量落盘，达到批量阈值时也会落盘；持续输入不会推迟周期写入。成功提交后通知界面刷新，界面另有定时读取作为兜底。写入失败会保留该批缓冲，供后续重试。

如需便携数据目录或隔离运行，可在启动工作台与后台服务的进程环境中设置同一个非空 `TOCCATA_DATA_DIR`，建议使用绝对路径。两个进程会从该目录读取 `config.json`，任务库固定放在该目录的 `tasks.sqlite`。非空 `db_path` 和 `socket_path` 可进一步指定键盘数据库与 socket 的绝对路径，Studio 会跟随这些设置。通过终端运行 SwiftPM 可执行文件时可直接继承该环境变量；已运行的应用需重新启动才能切换数据目录。

完整表结构和统计口径见 [shared/protocol.md](shared/protocol.md)。键盘热力图使用随包的妙控键盘布局，修改布局后需同步资源并重新构建；热力图配色由界面代码定义，外观由“月之亮面 / 月之暗面 / 跟随系统”统一控制，见 [shared/README.md](shared/README.md)。
